# QA dispatch

The shape is decided before merge — step 6's summary states it — and **a QA-needed change is not finished until its verdict is recorded**:

1. **Confirm the observable is reachable before promising it.** Read what the smoke subset actually selects (`packages/eval/src/smoke-subset.ts` is deterministic) and confirm the merge triggered a `Staging` run at all — a docs-path-only push does not. When the observable is outside the subset, widen that run with the existing `workflow_dispatch` inputs (`eval_smoke_size`, `eval_budget_micro_usd`) or put a targeted probe in the ticket. A promise the deployed run cannot reach is a blocker to fix first, not a QA ticket.
2. **Write the QA ticket** per the `qa-phase` skill's ticket contract: the observable (with its reachability evidence), the blast radius, the surfaces, the abuse angles, staging + merge SHA + `Staging` run id, and the spend cap (default $1 per run, ADR-0034).
3. **Dispatch the `qa` role** (per your harness adapter) in the background, with the QA ticket number, the staging URL, the merge SHA and the `Staging` run id in its prompt. The QA role gets **no worktree** — it is read-only on the repo and probes the deployed environment — and the todo duty is carried into its prompt scoped to its brief/probe/report phases (canonical bullet in Reliability & supervision).
4. **Verify the verdict once, one-shot**: `gh issue view <qa-ticket> --comments` shows a verdict of `verified`, `not verified`, or `blocked`, with per-probe evidence, the spend against the cap, and **every session erased or its non-erasure disclosed** (`sessionId`, contents, and expiry per the skill's safety rails — a disclosed session is compliant, not a failure); every real defect has its own linked ticket. A `not verified` verdict reports an escaped defect, and every defect the QA role files is one: each such defect owes the retrospective duty in `BUG-RETROSPECTIVE.md`. `not verified` or `blocked` → relay the failing probe to the user verbatim and send the defect tickets through the normal implement → review loop; the change is not finished. A green `Staging` run is not a verdict, and neither is a subagent's prose.
