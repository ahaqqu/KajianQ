# DB-gated test suites

A suite that only executes with a database declares `// @requires-postgres` (a line comment in the test file), and **gates with a skip** — `describe.skipIf(!process.env.DATABASE_URL)`, never an early `return` from a test body: a test that returns early reports a pass and skips nothing, so no report-reading gate can tell it from one that ran. The `postgres:contract` job derives its selection from that directive, so a new gated suite runs in CI without the workflow being edited. Over the files `vitest.config.ts` collects, the DB-less job fails on three things: a test file that skipped a test without the directive, whole or partial; a test file that reads `DATABASE_URL` in code position without it; and a declaration whose file skipped nothing, which means the gate is not a skip. It sees a read in code position in these spellings: the property (chained or not), a quoted or template subscript, a destructuring from `process.env`, `import.meta.env` or an `env` object, a subscript by a key the file binds to the name, and `process["env"]` / `import.meta.env`. A mention in a comment or in fixture text is not a read. Reads it does not see: one whose name the file never spells — built by concatenation, held in a value bound elsewhere, or returned by a helper module — and any read behind an alias of `process.env`. A suite that gates that way and returns early instead of skipping leaves the report nothing to see, and a test file the include globs do not collect is in no job at all.
