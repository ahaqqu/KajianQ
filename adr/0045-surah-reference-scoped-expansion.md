# ADR-0045: A surah reference in the question pulls that surah's children into context

## Decision

1. **The named surah's children are retrieved alongside the fused hits, never instead of them:** a direct store lookup of that surah's parent document and a bounded window of its children, run on the verbatim question rather than on a router sub-query, with no embedding, no model call and no dependence on the router's phrasing. A retrieved verse is a second anchor (ADR-0049).
2. **Detection is domain logic and lives in the domain pack.** It matches an explicit address, a surah name preceded by a marker word (never a bare name), or a description the curated table carries. The description table is bounded and whole-phrase: an entry is the whole phrase a question uses, complement included, so it fixes its Quran referent on its own — a positional description whose complement fixes it to the Quran — matched as the phrase it is after normalization, never a fragment, never a bare form whose referent a longer phrase moves. The phrases are curated per language, and a description the table does not carry is an accepted residual in every language, not a wider match. Each entry's expected mapping is pinned by the detector's test, so adding or changing one is a reviewed edit. An address's verse is validated against the surah's own verse count, so the trace never names a verse the surah does not have, and a form carrying no number records the surah alone rather than inventing a verse.
3. **The window begins at the reference:** the parent's opening position for a surah reference, and the named verse's own position for a verse reference, so a reference past the opening window is supplied by the same read. The parent is addressed by its opaque provenance key and the window by a lower bound in the parent's stable ordinal order.
4. **The expansion is bounded by an explicit, configurable cap** — `SCOPE_EXPANSION_CAP`, a non-negative integer where zero disables and a malformed value is a typed config failure rather than a silent default. A short surah comes back whole, a long one yields its deterministic window, and the cap reports its truncation instead of growing the prompt.
5. **The path is first-class on the trace.** Every added chunk reference carries an origin label, and a typed event records the scope, what was returned, the cap and whether it truncated; a recognised but empty scope is recorded too, and the label reaches the user-facing trace frame and the eval.
6. **The engine surface stays generic.** What crosses into the engine is the routed query's source text, the chunk origin label, the trace variant and one store read addressed by an opaque provenance key and an ordinal lower bound; the surah number, the citation grammar, the name table and the description table stay in the domain pack.

## Why

A short, formulaic verse is an unreachable semantic neighbour of a whole-surah meta-question, and the router's paraphrase flipped even the reachable verses in and out of the set — so the reference the user already stated is read, not inferred. A bare name is not a reference: almost every surah name is also an ordinary word or a divine name, which is what the marker requirement keeps safe. A fixed description is a reference in the same sense a name is when the tradition names it or the Quran's own numbering settles it, and a whole-phrase table with its mapping pinned by a test keeps that step finite and auditable; a general description matcher, a fuzzy match or a model call would infer an identity the user did not state. Reading from the named verse's own position is the same rule as reading from the surah's opening: the reference sets where the window starts, and the cap keeps the cost bounded. Context is the cost, so the cap is an operator's number and the trace shows what it spent, and a path that adds chunks without leaving a record is the silent machinery the trace exists to prevent.

Rejected: reference-augmented embeddings — a paid re-ingest with snapshot brackets and a gate revalidation, treating a stated identity as a similarity problem; a third lexical list in the rank fusion, which helps explicit addresses only and competes with the fused ranks instead of guaranteeing the reference's presence; stabilizing the failing gate only, which does not fix recall; bare-name matching; a model-based detector, a paid call where a string match is exact; a broad or fuzzy description detector; a window centred on the named verse with the cap split on both sides, because the read begins at the reference and the neighbourhood read supplies the verse before it; and a multi-surah window in one read, deferred because the budget and the trace carry one scope.

## Consequences

- The expansion is reported, not silent: each scored outcome persists its contribution and the trace frame carries the origin label, so on a question that names a reference the recall leg is satisfied by construction.
- A failure on the expansion read fails the retrieval — deliberately fail-closed and uniform with the fused reads, because degrading would let a store blip answer a whole-surah question with no part of that surah behind a successful response.
- Cost per scoped query rises by at most the cap in prompt, no vendor call is added, and an unscoped question pays nothing and issues no read.
- The trace and frame contracts grow additively, so persisted traces and older frames still parse, and the store seam's child read takes an ordinal lower bound that every adapter implements.
- **Revisit when** a name spelling no table rule reaches matters (an alias plus a test, not a wider match); a question phrased without a marker word measurably matters (a disambiguation rule that must keep the bare-name trap passing); a description the table does not carry measurably matters (a table edit plus its test, never a semantic resolver); the normalization's elongation collapse produces a false positive that stops being acceptable as it stands (narrowing the collapse reopens the spellings it fixed); a comparison question needs both scopes under one budget; or a future embedding re-ingest improves short-verse recall generally (the two are measured together, not assumed to compose).
