# ADR-0045: A surah read is deterministic, bounded, and triggered by the question or by a retrieved short surah

## Decision

1. **A surah's children are retrieved alongside the fused hits, never instead of them:** a direct store lookup of that surah's parent document and a bounded window of its children, with no embedding and no model call. Two triggers issue that read — the **verbatim question's own reference** (an explicit address, a name behind a marker word, or a whole phrase the curated description table carries) and **a retrieved verse whose surah fits the read's budget**. The first runs on the question, never on a router sub-query; the second runs on what retrieval returned, like ADR-0049's anchor. A retrieved verse is also a neighbourhood anchor (ADR-0049).
2. **Detection is domain logic and lives in the domain pack.** It matches an explicit address, a surah name preceded by a marker word (never a bare name), or a whole phrase the curated description table carries. The description table is bounded and curated: an entry is the whole phrase a question uses, complement included, and it is admitted only when the phrase itself fixes its Quran referent on its own — a positional description whose complement settles it to the Quran — and no natural qualifier moves that referent. It is matched as the phrase it is after normalization, never a fragment, never a bare form. The table carries no entry, and no phrase can be admitted until detection gains a boundary rule: with the current normalized-text match, a natural negative carrying the entry's words always prefix-matches, so the admission guard cannot pass for any entry. A positional phrase a revelation-order qualifier moves, and a tradition-named description whose referent rests on an attribution the product does not assert at retrieval time, are accepted residuals in every language, never a wider match. An entry's expected mapping and its referent-moving negative would be pinned by the detector's test, so admitting or changing one stays a reviewed edit. An address's verse is validated against the surah's own verse count, so the trace never names a verse the surah does not have, and a form carrying no number records the surah alone rather than inventing a verse.
3. **The reference sets the window's start; a completion reads from the surah's opening.** A named surah begins at its opening, a named verse at its own position, so a reference past the opening window is supplied by the same read. A completion begins at the parent's opening, because a short surah is one unit and the address the question needs may precede the verse retrieval returned — the one-ordinal neighbourhood read deliberately cannot reach it. The parent is addressed by its opaque provenance key and the window by a lower bound in the parent's stable ordinal order.
4. **The read is bounded by an explicit, configurable cap** — `SCOPE_EXPANSION_CAP`, a non-negative integer where zero disables and a malformed value is a typed config failure rather than a silent default. Both triggers **share one budget**: the named read spends it first and a completion uses what remains, and a surah whose verse count exceeds the budget is not a completion target, so the prompt never gains a long surah's text. A short surah comes back whole, a long one yields its deterministic window, and the cap reports its truncation instead of growing the prompt.
5. **The path is first-class on the trace.** Every added chunk reference carries an origin label, and a typed event records the scope, what was returned, the cap and whether it truncated — a completion records its surah under its own scope key; a recognised but empty scope is recorded too, and the label reaches the user-facing trace frame and the eval.
6. **The engine surface stays generic.** What crosses into the engine is the routed query's source text, the chunk origin label, the trace variant and one store read addressed by an opaque provenance key and an ordinal lower bound; the surah number, the citation grammar, the name table and the description table stay in the domain pack.

## Why

A short, formulaic verse is an unreachable semantic neighbour of a whole-surah meta-question, and the router's paraphrase flipped even the reachable verses in and out of the set — so the reference the user already stated is read, not inferred. A bare name is not a reference: almost every surah name is also an ordinary word or a divine name, which is what the marker requirement keeps safe. A fixed description is a reference only when the phrase itself fixes the Quran referent and no natural qualifier moves it: a positional phrase moves under a revelation-order qualifier, and a tradition-named description rests on an attribution the product does not assert at retrieval time — one such attribution is disputed — so either would make the deterministic read name a surah the question did not, the failure this table must not ship. A whole-phrase table with its mapping pinned by a test keeps that step finite and auditable, and a general description matcher, a fuzzy match or a model call would infer an identity the user did not state. Reading from the named verse's own position is the same rule as reading from the surah's opening: the reference sets where the window starts, and the cap keeps the cost bounded.

The completion trigger exists because the fused tracks can return one verse of a short surah and leave its opening — the verse that may name what the question asks about — outside the context, while the neighbourhood read stops one ordinal from the returned row and spends its budget on the best-ranked windows. Reading a short surah whole is the same deterministic lookup on a second trigger, and the fits-the-budget condition keeps it off every long surah. Context is the cost, so one budget serves both triggers and the trace shows what it spent; a path that adds chunks without leaving a record is the silent machinery the trace exists to prevent.

Rejected: reference-augmented embeddings — a paid re-ingest with snapshot brackets and a gate revalidation, treating a stated identity as a similarity problem; a third lexical list in the rank fusion, which helps explicit addresses only and competes with the fused ranks instead of guaranteeing the reference's presence; stabilizing the failing gate only, which does not fix recall; bare-name matching; a model-based detector, a paid call where a string match is exact; a broad or fuzzy description detector; a tradition-named description, whose referent rests on an attribution the retrieval does not assert; a window centred on the named verse with the cap split on both sides, because the read begins at the reference and the neighbourhood read supplies the verse before it; widening the neighbourhood radius to reach a surah's opening, which turns every window into a sweep and spends the budget on unrelated verses; completing every retrieved verse's surah, which would put a long surah's text into the prompt; and a second configurable budget for the completion, which would let one query's surah reads grow past the ceiling the operator set.

## Consequences

- The expansion is reported, not silent: each scored outcome persists its contribution and the trace frame carries the origin label, so on a question that names a reference — or retrieves a verse of a short surah — the recall leg can be satisfied by construction.
- A failure on the expansion read fails the retrieval — deliberately fail-closed and uniform with the fused reads, because degrading would let a store blip answer a whole-surah question with no part of that surah behind a successful response.
- Cost per scoped query rises by at most the cap in prompt, no vendor call is added, and an unscoped question pays nothing and issues no read; a completion adds at most its surah's children out of the same budget.
- The eval's expansion block counts completion chunks on the scope path, because they are the same read; the trace distinguishes a named reference from a completion by the event's scope key.
- The trace and frame contracts grow additively, so persisted traces and older frames still parse, and the store seam's child read takes an ordinal lower bound that every adapter implements.
- **Revisit when** a name spelling no table rule reaches matters (an alias plus a test, not a wider match); a question phrased without a marker word measurably matters (a disambiguation rule that must keep the bare-name trap passing); a description the table does not carry measurably matters (admission first gains a boundary rule — the current normalized-text match vetoes every entry — then an admitted phrase plus its referent-moving negative, never a semantic resolver); the normalization's elongation collapse produces a false positive that stops being acceptable as it stands (narrowing the collapse reopens the spellings it fixed); the shared budget truncates a completion whose missing verse the question needs (a second budget is a cost decision, measured first); a comparison question needs both scopes under one budget; or a future embedding re-ingest improves short-verse recall generally (the two are measured together, not assumed to compose).
