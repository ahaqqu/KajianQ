# Neon Postgres+pgvector behind a RagStore adapter (not D1/Vectorize)

The fork keeps the agentic-project-template's Workers + React PWA shape, but replaces D1 and the local-first sync package with Neon Postgres + pgvector, accessed only through a RagStore adapter in `packages/infra`. The Smart Router's core is rich SQL metadata filtering (`madzhab`, `grade`, `source_type`, `principle_tags`) plus hybrid search (pgvector HNSW + tsvector BM25 + RRF) — neither D1 (SQLite, no vector extension) nor Cloudflare Vectorize (weak metadata filtering) can express it, and Vectorize would lock the DARS engine to Cloudflare, violating the reusability goal. The adapter keeps engine packages runtime-agnostic; ingestion runs as Bun scripts off-Workers; chat history and traces also live in Postgres. Deliberate deviation from the template — do not "simplify" back to D1. Neon free tier covers small scale; R2 stores raw Shamela exports and `text_raw` backups.
