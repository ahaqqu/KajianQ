# Deep Think: iterative budget-capped retrieval mode, never read-all

Hard questions need broader coverage than the default top-k (8–12 chunks) provides, but "read all found documents into the context" is rejected: long contexts degrade per-passage recall (lost-in-the-middle), irrelevant material actively misleads the generator, and cost/latency grow 50–100×. KajianQ instead offers an opt-in Deep Think mode: iterative retrieval rounds (draft answer → gap/contradiction detection → re-retrieve) over a deep candidate pool (50–100 chunks), with the cheap tier scoring candidates for relevance before assembly, under hard caps on rounds, context tokens, and per-query cost — all traced. The Trace shows coverage explicitly (passages examined vs. relevant vs. used), making comprehensiveness a visible, auditable property. The default chat path keeps top-k discipline unchanged. Deep Think must beat the baseline on the Golden Set (recall + faithfulness at bounded cost) before it is promoted beyond opt-in.
