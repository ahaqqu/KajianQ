# ADR-0044: The VPS serving path — a Bun process behind nginx, Postgres over TCP, and a single-shot cutover

## Decision

1. **The serving path is a plain Bun process behind nginx** — loopback-bound because the reverse proxy is the only public ingress, draining on SIGTERM, and configured from a root-owned env file rather than `argv` or the unit text, which the process table and the journal would expose. The Cloudflare Worker entry, its Durable Object limiter and its object-storage binding are deleted.
2. **Single-shot cutover, with no rollback runway.** Staging is verified first and production cuts over in one step, with the snapshot criteria and the restore drill strict. One box exists, labelled `staging`; production is deferred, not pending — a production dispatch deploys the same box behind its approval gate — and the workflow, environment and gate names stay as they are.
3. **The deployer lives in its own home, outside `apps/`** — one build → upload → helper swap → smoke implementation called by the deploy workflow, and provisioning stays under `provision/vps/`. Where a deploy lands, and the credential it lands with, are the dispatching environment's own state: the box, the deploy identity, the tree label, the public URL and the deploy key belong to that environment's scope rather than to the repository, and the deploy path never substitutes a default for a value its scope does not carry.
4. **nginx replaces the bootstrap's Caddy, and the CDN proxy stays off.** The API reads the client address from a header nginx overwrites from the connection's own remote address, so per-IP metering is honest; with the CDN proxy on, that address is an edge address and the metering collapses silently, so enabling it requires real-IP configuration first.
5. **The adapter speaks Postgres over TCP and is named for its dialect:** the driver replaces the vendor's serverless transport, the provider is `postgres`, and the connection variable is the vendor-free `DATABASE_URL`. Engine code still never imports a driver.
6. **One process, one timer, one deploy identity.** The limiter is the bounded in-memory backend with digest-named counters; the nightly reclamation is its own timer. A dedicated unprivileged account uploads the deploy artifact to `/srv/vps-incoming` and invokes the root-installed `vps-deploy` helper, which verifies and swaps `/srv/kajianq` as `root:root`; the identity does not write the deployed tree. Its grant is that helper (deploy, `--rollback` and the four bounded service verbs), the cron proof (`systemctl start kajianq-cron.service`) and the two read-only doctor diagnostics (`nginx -t`, `certbot certificates`); the legacy `systemctl restart kajianq-api.service` is bridge-only. The contract and the grant live in the host-configuration repository ([ahaqqu/vps](https://github.com/ahaqqu/vps), [DEPLOY](https://github.com/ahaqqu/vps/blob/main/docs/DEPLOY.md)). The name is fixed rather than configurable, because a grant is per-username: the account, the grant and the deploy identity are pinned by test, and the serving account cannot write that tree.
7. **The reviewer chain is paid and, for the current key set, same-vendor.**

## Why

The superseded path had application code owning hosting, a partly destructive deploy and an end-to-end harness on a runtime production would never use — the criterion asks for the opposite.

- **Single-shot is a choice against a measured condition,** recorded so a future reader does not "fix" it: there is no live traffic to preserve, and relaxing uptime tolerance relaxes no snapshot criterion.
- **nginx is fixed because the access-log format must be controlled field by field** — the address-bearing access-log policy — and the code already assumes its semantics.
- **The lazy driver contract is documented because its failure is silent:** an eager driver runs transaction statements on separate pooled connections with no error, tearing the atomicity of session creation and of a transaction batch.
- **One process justifies dropping the Durable Object; the guarantee moves, not the rule** — the limiter still holds one digest-named counter per key, which is the retention notice's claim.
- **The deploy grant is the commands the deploy path uses, with the bridge's legacy entries kept only until their path is retired,** because the arrangement it replaces had no executable existence and broke the first deploy after its removal; an unused grant is privilege widening that looks harmless, so the legacy restart is a named, temporary exception rather than an ongoing allowance.
- **Same-vendor review is accepted deliberately,** so the anti-self-review property is relaxed rather than drifted into.
- Rejected: keeping the Worker as a rollback, when the window is gone and the git history is the rollback; the vendor's serverless driver against a self-hosted store, which means a vendor's proxy mediating access to your own database; the vendor's name as a provider or environment alias, which would outlive its reason and mislead the next reader about where the data lives; an in-process interval for the reclamation, and a container instead of the service manager (deferred), because two failure modes must not share one process.

## Consequences

- The store adapter is the tree's only driver importer, exempted by the boundary gate explicitly along with the migrations CLI and the search probe, so the DB-client rule stays meaningful rather than relaxed wholesale.
- The staging Golden Set smoke is the post-cutover health signal, and the end-to-end suite boots the same entry the deploy ships, so the tested host is the served host.
- The contract suite is self-contained — a database service container with the migrations applied — so it runs in every environment including fork pull requests; the hardening test gates the grant, the fixed account name and the tree's ownership; and the deploy path, the units, the grant, the proxy site, the boot and reclamation entries and the driver adapter stay behind their existing seams.
- **Revisit when** the API scales out beyond one process (the limiter needs a shared counter); a live-user base arrives (a rollback runway and a blue/green shape become a new decision); production is provisioned (a second host or tree behind the production gate); a second deploy target arrives, or a human operator deploys from a workstation (its key joins the same authorized keys — supported, a separately recorded choice); a vendor key becomes load-bearing in staging (promote it to a required environment guard); a second paid vendor key is provisioned (cross-vendor review returns by configuration alone); the deploy identity's trust is judged insufficient (a root-owned installer that fetches the artifact itself); or the box's ops burden proves disproportionate.
